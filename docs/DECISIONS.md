# Decisions log

Every architectural decision and every contract change is recorded here with its reason. Only the lead edits `contracts/` and this file. Status values: **accepted**, **provisional** (to be re-checked against measurements), **superseded**.

Plan reference: `docs/PLAN.md` section 3. Dates are 2026-11-20 unless stated.

## Architecture decisions

| ID | Decision | Reason | Status |
|---|---|---|---|
| D-1 | "End-to-end delay" gate = capture (optical stamp) to the frame being written to the egress socket, **p95 <= 5.0 s**. Viewer-side YouTube latency is recorded as an informational number, not gated | YouTube adds roughly 3-5 s of its own on top of anything we do, so a viewer-side 5 s is unreachable at D=4. Approved by "Proceed" | accepted |
| D-2 | Event transport: in-process typed bus inside the engine for the hot path (frames never serialised); **ZeroMQ PUB/SUB** (broker thread in the engine, `ipc://`) for cross-process events and commands; JSON wire format; `InProcessBus` fake for tests | Engine is the always-on process, so hold works if api dies. pyzmq is small and mature. No Redis/NATS to install | accepted |
| D-3 | STT: Sarvam `saaras:v4` codemix over WebSocket primary (about 29 INR/h, 22 languages, REST 60/min, 20 concurrent WS). Groq `whisper-large-v3-turbo` secondary (0.04 USD/h, but 20 RPM so chunks >= 3 s, <= 18 requests/min). faster-whisper base int8 on CPU local fallback. One `SpeechToText` protocol, raced per segment | Sarvam covers Hinglish and the five target languages. Groq's rate limit blocks it as primary. Local is for outages and offline mode | accepted |
| D-4 | Mute granularity: segment-level (<= 1.5 s, 0.2 s padding) by default because Sarvam WebSocket returns no timestamps; word-level when a timestamped result arrives. Phase 0 spike (T0.6) checks Sarvam REST timestamps (UNVERIFIED) | Honest about collateral muting; evidence decides | provisional |
| D-5 | Spoken-PII logic: rules first (digit words in Hindi/English/regional, Devanagari digits, "double/triple", spoken UPI, phone structure, address cues); Groq `gpt-oss-20b` only for ambiguous cases, 0.7 s timeout; on timeout an ambiguous voiced segment is muted | Deterministic fast path; LLM cost stays small; fail toward privacy | accepted |
| D-6 | Chat classification cascade: rules/keyword lists (Hinglish Latin, Devanagari, misspellings), scam/UPI link patterns, doxxing (streamer private terms + phone/address patterns), then Groq `gpt-oss-20b` in batches of about 20 within 30 RPM. MuRIL fine-tune is a later option | Rules answer in under 5 ms; the LLM handles the rest | accepted |
| D-7 | Captions: Sarvam translate (Mayura for code-mixed, 11 languages; sarvam-translate for 22), 2 INR per 1,000 chars. IndicTrans2 dist-200M local in `demo` only (gated on Hugging Face). Burned into the video on the delayed timeline with Noto Indic fonts (OFL) and libraqm for correct shaping | Captions are ready before display because of the delay | accepted |
| D-8 | Profiles: `config/profiles/{dev,demo}.yaml` over defaults in `contracts/config.py`, env overrides. `dev`: stride 3, GPU optional with a 3.5 GB cap, no local IndicTrans2. `demo`: stride 2, GPU on, 7 GB cap, local STT on GPU, local captions. Same code, config only | CLAUDE.md rule | accepted |
| D-9 | Indian-script OCR: signboards are **detection-only mask-all-text** (script-agnostic, covers Kannada and Bengali). Recognition only on crops for structured PII (Aadhaar, PAN, plates, phone, PIN, UPI ID, email, game IDs) with en/latin, devanagari, ta, te recognisers via RapidOCR. Kannada/Bengali recognition is an optional EasyOCR extra, not on the real-time path | PP-OCRv5 has no Kannada or Bengali recogniser; masking all sign text needs none | accepted |
| D-10 | Detector framework: own `Detector` protocol with plugin autodiscovery (`vision/detectors/<id>/__init__.py` exports `DETECTOR`), FAST/ACCURATE/SLOW lanes, ORT session helper, declared `vram_mb` | Lets detector tasks run in parallel with no shared files | accepted |
| D-11 | Ultralytics and InsightFace are not load-bearing. Defaults: YuNet+SFace for faces, OCR-first plates. YOLO plate weights and InsightFace buffalo_s are optional adapters behind extras, flagged "replace before commercial release" | Avoids AGPL and non-commercial weights on the default path; PrivaStream ships no weights anyway | accepted |
| D-12 | Python stack: 3.11 via `uv`; `onnxruntime-gpu==1.26.0` (never with plain `onnxruntime`); torch 2.11 cu128 only as an optional extra; `opencv-contrib-python-headless` only; numpy <= 2.4; av 16.0.1 | Fixes the three-OpenCV conflict, Python-3.12-only wheels and the Pascal pins. cu128 torch wheels stop at 2.11 | accepted |
| D-13 | YouTube chat: poll `liveChatMessages.list` honouring `pollingIntervalMillis` with a quota governor (10k units/day: read 5, delete 20, ban 200). Prefer hide-on-our-side and delete over bans. gRPC `streamList` is an upgrade task (UNVERIFIED that a clean Python client exists) | Quota arithmetic | provisional |
| D-14 | Twitch: EventSub WebSocket `channel.chat.message` via twitchAPI 4.5.0 without monkeypatching private hooks; Helix delete (`moderator:manage:chat_messages`) and timeout (`moderator:manage:banned_users`) | Scopes differ from IRL Shield's | accepted |
| D-15 | Encoding/outputs: x264 veryfast by default, NVENC when `h264_nvenc` exists. 720p30 at about 4.5 Mbps, keyframe every 2 s (GOP 60), AAC 128 kbps 48 kHz stereo. One encode feeds N destinations. YouTube via `rtmps://a.rtmps.youtube.com:443/live2/<key>` through the TLS forwarder | YouTube ingest guidance | accepted |
| D-16 | Hotkey: Windows-side helper `scripts/hold_hotkey_win.py` calls the engine's local hold endpoint; plus an in-app key and a mobile button | A WSL process cannot see global Windows hotkeys | accepted |
| D-17 | Privacy: no archive, no seal, no image or raw-PII logging. Logs hold category, time, confidence and box. Flagged chat messages are never logged raw. Tokens RAM-only (optional OS keyring) | CLAUDE.md data rules | accepted |
| D-23 | Retroactive hold kept: pressing hold also masks the last `retro_seconds` (default 3.0, clamped to `delay_seconds - 0.5`) of buffered frames and audio | The delay buffer makes it possible; a streamer who notices a leak can still stop it. Approved by "Proceed" | accepted |
| D-24 | Phase 0 installs (venv, pip packages, hash-pinned MediaMTX, models, `pyzmq`) are approved as part of the plan but run only inside task T0.1. System-level changes (`.wslconfig`, Hyper-V firewall, `apt`) need the user's admin rights and are never done by an agent | Global rule: ask before installing anything | accepted |

## Environment notes (facts found while planning)

- Dev laptop: i5-13450HX (6P+4E, 16 threads), RTX 3050 **6 GB**, driver 581.86; WSL2 Ubuntu 24.04 ships Python 3.12.3 only (3.11 comes from `uv`). `h264_nvenc`, `libsrt` and `libx264` all work in WSL2 ffmpeg 6.1.1.
- No `.wslconfig` exists yet (WSL is on NAT); mirrored networking is a user action (docs/PLAN.md section 9).
- Contract tests in Step 0 ran on Windows Python 3.11.9 (109 passed, 1 skipped) (pydantic 2.13.5, pydantic-settings 2.15.0, pytest 8.3.2, ruff 0.15.20). That install's numpy is broken, so the one numpy-backed fake test is skipped there. The real environment arrives in T0.1.
- `reference/privastream/requirements.txt` is UTF-16 encoded; never feed it to pip.
